# `v0.4.1-rc.4` Scheduled Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a weekly broad pinned-Xray interop/resource gate and a warning-only focused Xray-core `main` smoke without weakening the exact blocking RC release contract.

**Architecture:** Keep `scripts/check-rc-interop.sh` as the independent release authority with its literal v26.7.28 SHA. Add separate scripts and workflow jobs for scheduled coverage. The local interop test binary accepts an override only as an exact resolved 40-character lowercase commit; the main-smoke script supplies that commit explicitly. The pinned scheduled script independently rejects any other checkout. Neither scheduled job participates in prerelease publication dependencies.

**Tech Stack:** GitHub Actions YAML, Bash, Rust integration-test harness, Go 1.26.5, Rust 1.96.0.

**Depends on:** [RC4 hardening design](../specs/2026-08-28-v0.4.1-rc.4-hardening-design.md). It can be implemented in parallel with the [XHTTP lifecycle plan](2026-08-28-v0.4.1-rc.4-xhttp-lifecycle.md).

**Followed by:** [benchmarks and documentation](2026-08-28-v0.4.1-rc.4-benchmarks-and-docs.md), then [release orchestration](2026-08-28-v0.4.1-rc.4-release-orchestration.md).

- [ ] **Step 3: Implement the strict helper.**

Add:

```rust
const XRAY_CORE_EXPECTED_REVISION_ENV: &str = "XRAY_CORE_EXPECTED_REVISION";

fn expected_xray_checkout_revision(override_value: Option<&str>) -> Result<&str, String> {
    match override_value {
        None => Ok(PINNED_XRAY_CORE_REVISION),
        Some(value)
            if value.len() == 40
                && value
                    .bytes()
                    .all(|byte| byte.is_ascii_digit() || (b'a'..=b'f').contains(&byte)) =>
        {
            Ok(value)
        }
        Some(value) => Err(format!(
            "{XRAY_CORE_EXPECTED_REVISION_ENV} must be an exact 40-character lowercase hexadecimal commit, got `{value}`"
        )),
    }
}
```

In `assert_xray_checkout_revision`, read the optional environment variable,
validate it through the helper, compare `git rev-parse --verify HEAD` to that
exact value, and print one diagnostic when an override is active. Branch
names, `HEAD`, abbreviated SHAs, and uppercase SHAs must remain invalid.
