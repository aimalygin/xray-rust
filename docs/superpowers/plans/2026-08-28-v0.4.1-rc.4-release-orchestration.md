# `v0.4.1-rc.4` Release Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce matching, checksum-bound `v0.4.1-rc.4` GitHub prereleases for `xray-rust` and `xray-rust-mobile`, with every required CI gate green and no crate, GitHub Packages, Maven Central, or other registry publication.

**Architecture:** Release core first from one clean reviewed commit and immutable annotated tag. Accept its prerelease only after the tag workflow succeeds. Then derive every mobile core identity from that exact local/remote tag, prepare mobile metadata with the required all-zero Apple checksum sentinel, run the two-phase Apple artifact/checksum-PR workflow, and tag only the merged checksum commit. Verify remote tag objects, asset digests, release channel flags, manifest content, and Maven-job skip state. Any source or workflow correction after a pushed tag becomes RC5; tags are never moved.

**Tech Stack:** Cargo, Git, GitHub CLI/API, GitHub Actions, Bash, SwiftPM checksum workflow, Gradle/Android release pipeline.

**Depends on:** Complete and verify the [XHTTP lifecycle](2026-08-28-v0.4.1-rc.4-xhttp-lifecycle.md), [scheduled compatibility](2026-08-28-v0.4.1-rc.4-scheduled-compatibility.md), and [benchmarks/documentation](2026-08-28-v0.4.1-rc.4-benchmarks-and-docs.md) plans. The benchmark plan freezes the RC4 version before measurement and commits evidence afterward without changing build or harness inputs.
