# `v0.4.1-rc.4` Benchmarks and Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish fresh RC4 release-mode benchmark evidence against the exact Xray-core v26.7.28 revision and the resolved stable sing-box v1.13.20 release, then reconcile public documentation with the implemented and published state.

**Architecture:** Preserve the v26.5.9 publication as immutable history. Store the RC4 publication in a new date-labelled directory containing reviewed summaries, commands, environment/comparator manifest, and its own charts. Raw samples remain outside Git as one checksum-addressed archive. A hermetic validator rejects incomplete provenance, debug/dirty runs, wrong comparator revisions, fewer than five runs, missing scenarios, and non-OK summaries before CI accepts the publication.

**Tech Stack:** Existing `xray-bench` release harness, Rust chart renderer, Bash, Python 3 standard library, JSON/CSV/SVG, GitHub API for stable-release discovery.

**Depends on:** Complete the [XHTTP lifecycle](2026-08-28-v0.4.1-rc.4-xhttp-lifecycle.md) and [scheduled compatibility](2026-08-28-v0.4.1-rc.4-scheduled-compatibility.md) changes first so measurements describe the final candidate behavior.

**Followed by:** [release orchestration](2026-08-28-v0.4.1-rc.4-release-orchestration.md).
