# `v0.5` reliable multi-node foundation design

Date: 2026-08-31
Status: accepted for implementation

## Release decision

`v0.4.1-rc.4` remains immutable and is the final candidate on the `0.4`
development line. Development proceeds directly to `v0.5.0`; a stable
`v0.4.1` is not required before Phase 2 work starts. Matching core and mobile
release candidates will use canonical `v0.5.0-rc.N` versions after feature
freeze. Until that freeze, core workspace packages use the non-release
development version `0.5.0-dev.0` and no public tag is created from it.

The final `v0.5.0` scope includes every Phase 2 DNS, outbound-selection, and
mobile-SDK item in the roadmap together with the carried hardening gates. RCs
stabilize that complete surface; they do not serve as an open-ended feature
development channel.

## Delivery order

1. Add ABI minor-version and capability discovery across C, Swift, and Kotlin.
2. Introduce the outbound graph/factory ownership seam.
3. Add selector groups, URL tests, health state, deterministic failover,
   bounded load balancing, and validated cycle-free chaining.
4. Expose atomic selection and health snapshots through the versioned C ABI.
5. Add managed DoH and DoT, then DoQ where lifecycle/resource evidence permits
   reuse of the existing QUIC stack.
6. Add negative caching, bounded stale-while-revalidate, an injectable system
   resolver, and explicit bootstrap-route behavior.
7. Add typed connection inventory/close, per-outbound accounting, health, and
   structured diagnostic events with Apple/Android parity.
8. Complete the carried fuzz, controlled-network, and physical-device gates,
   then freeze the feature set and create `v0.5.0-rc.1`.

## First vertical slice: ABI discovery

ABI major 1 remains backward compatible. This slice adds ABI minor 1 and a
64-bit capability mask without changing any existing function or structure.

The C boundary adds:

- `xray_ffi_version_minor()`, returning the additive ABI revision;
- `xray_ffi_capabilities()`, returning a bitwise capability mask;
- named capability bits for the existing config, lifecycle, TUN, and
  diagnostic surfaces.

The bit mask is descriptive, not a substitute for ABI-major validation. A
consumer rejects a different major, requires at least the minor revision used
by its wrapper, and checks capability bits before using optional future APIs.
Unknown bits must be preserved and ignored. New optional `v0.5` APIs add a bit
in the same change that adds the API.

Swift exposes value types for the ABI version and an `OptionSet` capability
mask. Kotlin exposes an ABI-version value, a capability enum, and an immutable
info object with a `supports` query. Both adapters validate major 1 and minimum
minor 1 before allocating a core handle.

The standalone `xray-rust-mobile` repository remains pinned to immutable RC4
while this core work is untagged. Its adapter snapshots and release metadata
are updated together after a reviewed core milestone exists; development must
not make an RC4 release checkout claim provenance from an untagged dirty core.

## Compatibility and testing

- Existing ABI-major-1 symbols and structure layouts remain unchanged.
- Rust tests pin the major, minor, exact supported mask, and unknown-bit
  behavior.
- Header and native-artifact tests require the new declarations and exports.
- Swift tests cover version acceptance/rejection and capability membership.
- Kotlin JVM tests cover capability membership without loading native code;
  native adapter checks verify the JNI discovery functions and validation
  order.

## Second vertical slice: outbound ownership seam

The existing router combined three responsibilities: immutable configured
topology, routing-policy selection, and lazy construction of protocol handlers.
The second slice separates them without changing route behavior:

- `OutboundGraph` owns ordered nodes, graph-scoped opaque node identities,
  first-tag resolution, and the effective default reference;
- `OutboundFactory` belongs to exactly one graph and owns all lazy TCP, UDP,
  DNS, and shared VLESS handler caches;
- `OutboundRouter` retains only routing and DNS-prefilter policy and resolves
  its result through the graph/factory pair.

`Core` constructs and owns this trio before start instead of rebuilding the
router inside `Core::start`. Graph-scoped identities make a foreign-node lookup
fail closed rather than indexing another factory. Duplicate tags still resolve
to the first configured outbound, an omitted default still selects the first
node, a missing explicit default still fails only when selected, and unsupported
handlers remain lazily rejected. Two routers backed by the same factory share
the same compiled handler and stateful transport pools.

This slice deliberately adds no mutable selector state and no config syntax.
The next slice can add selector nodes and a small atomic selection overlay while
keeping leaf handlers and their pools owned by the existing factory.

## Third vertical slice: selector groups and atomic override

The routing parser now models Xray's `routing.balancers` and `balancerTag`
shape. `selector` values retain upstream prefix semantics, and each immutable
graph expands them against tagged leaf outbounds in lexicographic tag order.
Group nodes live in the graph identity namespace but are never handed to the
protocol factory as leaves.

The shared factory owns one `OutboundSelectionOverlay`. `random` chooses per
new flow and `roundRobin` uses one atomic cursor per group. A validated override
stores one member index atomically, is visible through every router sharing the
factory, and does not disturb established flows or compiled handler pools.
Clearing the override returns the group to its configured strategy. A snapshot
reports the monotonic update revision, immutable candidate tags, and current
override without exposing internal node indexes.

Empty candidate sets use `fallbackTag` and otherwise fail closed. Unknown
groups and non-member override targets are typed errors. Health-dependent
`leastPing`/`leastLoad`, URL tests, failover health policy, chaining, and the C
ABI surface remain intentionally outside this slice.

## Fourth vertical slice: URL health and deterministic failover

The parser now models Xray's top-level `observatory` fields and `leastPing`
strategy. Probe subjects retain outbound-tag prefix semantics and are expanded
through the immutable graph. Missing URL and interval values use Xray's
defaults; explicit intervals are bounded to 1 second through 24 hours, every
request has a fixed 5-second timeout, and concurrent mode is capped at four
active probes for mobile resource safety.

The observer is owned by `Core` lifecycle and starts after a configured startup
probe succeeds. It reuses the same direct-by-tag HTTP(S) probe path, destination
and bootstrap resolvers, protected dialer, and cached outbound handlers. Stop
cancels it with the other runtime tasks. Probe failures are reduced to typed,
redacted categories rather than retaining raw URLs or nested error strings.

One atomic health record per tagged leaf stores unknown/healthy/unhealthy
state, measured delay, timestamps, consecutive failures, and the last typed
failure. A shared update lock gives snapshots a coherent revision while new
flow selection remains lock-free. Random and round-robin exclude known-dead
candidates but keep unknown candidates eligible. `leastPing` considers only
successfully observed candidates and uses sorted tag order as its deterministic
equal-delay tie-break. An empty eligible set uses `fallbackTag`; a host override
remains authoritative and affects only new flows.

## Fifth vertical slice: mobile selection and health ABI

ABI major 1 remains unchanged and minor 2 adds distinct outbound-selection and
outbound-health capability bits. The C surface exposes validated atomic
override/clear calls plus two-pass UTF-8 JSON snapshots. Selection and health
documents have their own `schemaVersion: 1`, monotonic revision, stable typed
fields, and no raw URL, endpoint, credential, or free-form probe error.

Swift and Kotlin expose equivalent typed models and public core methods. Both
adapters check the relevant capability before using an optional symbol and
reject unknown snapshot schema versions. The shared-call gates allow override
and snapshot operations while the core is running without overlapping
lifecycle/free. C contract tests, SwiftPM tests, Kotlin JVM tests, the Apple
XCFramework matrix, and the four-ABI Android JNI/AAR build cover this slice.

Cycle-free chaining and bounded `leastLoad` remain the next outbound-selection
work.

## Sixth vertical slice: validated transport-layer TCP chaining

The parser accepts Xray's outbound `proxySettings` only when `tag` is non-empty
and `transportLayer` is explicitly `true`. This maps to Xray's dialer-proxy
shape: the selected outbound keeps its own security and stream transport while
its raw TCP carrier is opened through the referenced outbound. The default
protocol-layer form remains rejected because it has different handler
semantics and would be unsafe to approximate.

Every configured edge is resolved through the graph's first-tag index before
the core starts. A missing target, `transportLayer: false`, self-cycle, or
multi-node cycle is a typed graph error. The factory wraps cached leaf handlers
instead of rebuilding them, so multi-hop chains preserve the same gRPC/XHTTP
pools and immutable node identities as direct selection.

`TransportDialer` owns an optional resolved-TCP carrier boundary. The default
boundary still opens the protected platform socket. A chain replaces only that
raw carrier operation; TLS, WebSocket, HTTPUpgrade, gRPC, and TCP-backed XHTTP
continue through the existing transport dispatcher above the nested stream.
This keeps Android `VpnService.protect(fd)` at the terminal socket and prevents
an outer transport from silently opening a side socket around the graph edge.

The initial compatibility boundary is intentionally TCP-only. Chained UDP and
DNS handlers, protocol-layer `transportLayer: false`, REALITY over an arbitrary
preconnected stream, and XHTTP HTTP/3/QUIC fail closed. Supporting those shapes
requires protocol-appropriate datagram and REALITY lifecycle seams; they must
not be inferred from the TCP implementation.

## Seventh vertical slice: bounded `leastLoad`

The parser accepts Xray's `leastLoad` strategy with a mobile-bounded settings
subset: top-N `expected` is capped at 16, `maxRTT` and every baseline cannot
exceed the observer's fixed five-second timeout, and the number of baselines
and literal tag-cost rules is capped. Regex costs and the undocumented
zero-value automatic coefficient fail closed rather than adding an
uncontrolled matching path to every flow selection.

Each leaf keeps a 16-result rolling probe window. A serialized health update
publishes its count, failure count, mean, and population deviation as one
packed atomic value, so selection remains lock-free and cannot combine fields
from different window revisions. Healthy candidates are filtered by latest RTT
and failure tolerance, then ordered by cost-weighted deviation, mean RTT,
failures, descending sample count, and tag. Squaring Xray's
`deviation * sqrt(cost)` score produces the same ordering without floating
point in the hot path.

The strategy follows Xray's baseline/expected selection shape and randomly
distributes new flows only inside the resulting bounded top-N. Unknown and
currently unhealthy candidates remain ineligible; an empty result uses the
existing fallback path. Host overrides stay authoritative and bypass dynamic
ranking, preserving the established atomic-switch contract.

## Eighth vertical slice: core connection-management foundation

One core-owned registry now assigns nonzero monotonic identities after a
SOCKS/HTTP TCP request has a routed target and selected outbound. Entries move
from `Opening` to `Active` only after the outbound has opened and the inbound
success response has been sent. A revisioned, ID-sorted snapshot exposes typed
inbound/outbound tags, network, target, and start time without retaining peer
credentials or transport errors.

Each entry owns a cancellation watch channel. `close(id)` marks the request in
the registry before signalling it, so dropping an in-flight dial or relay
cannot race accounting attribution. The lease removes itself on every return,
panic unwind, listener shutdown, or host close. Unknown IDs are typed errors.

The relay increments per-entry uplink/downlink atomics after each successful
write, including SOCKS sniff payload sent before the generic copy loop. On
completion the registry folds those counters into stable per-outbound totals,
so cancellation and later I/O failure cannot erase bytes already transferred.
This slice initially covered routed SOCKS and HTTP TCP flows. The next
increment applies the same lease to TUN TCP and UDP transport sessions: the
selected outbound tag is retained independently of timing diagnostics,
`Opening` covers outbound setup, `Active` begins after the socket or tunnel is
ready, and host close cancels both setup and relay. TCP batching and UDP
framing account logical payload bytes only after successful transport I/O.
ABI 1.3 adds one coherent connection-management capability with versioned JSON
inventory/accounting snapshots and addressable close. Swift and Kotlin expose
the same typed schema and reject unknown schema versions.

## Ninth vertical slice: Android structured-diagnostic parity

The existing ABI-major-1 TUN diagnostic capability and seven C event queues
remain unchanged. Android now projects the same TCP slow-flow, flow-summary,
remote-write-slow, and open-error events plus UDP slow-flow, response-gap, and
QUIC-blocked events that Swift already exposes. JNI converts each destructive
single-event poll into one private typed wire object; Kotlin validates its kind
and field count before returning public immutable event models and drains no
more than the caller's `maxEvents` budget. Empty queues remain a normal empty
list, while malformed native shapes fail closed.

## Tenth vertical slice: SOCKS UDP connection management

Each admitted SOCKS UDP `(client, target)` task registers only after routing
has selected an outbound, retaining the selected tag and effective dial target.
The entry remains `Opening` through Freedom resolution/socket setup or VLESS
stream setup, becomes `Active` when its transport is ready, and consumes the
same host-close signal during setup and relay. DNS outbound flows become active
before their first bounded message execution. Accounting records logical UDP
payload bytes only after successful outbound execution/read or transport I/O;
SOCKS framing bytes are excluded. Association shutdown, idle expiry, admission
eviction, errors, and host close all drop or finish the same lease.

## Eleventh vertical slice: routed managed DNS over TLS

The parser accepts strict authority-only `tls://host[:port]` name servers,
using port 853 by default and preserving the existing per-server selection,
tag, timeout, query-strategy, and failover policy. The policy compiler selects
a distinct routed TLS query kind rather than approximating DoT as plain TCP.

The runtime first resolves a domain endpoint through the non-recursive
bootstrap role and opens the selected Freedom, VLESS, or chained TCP carrier.
It then performs certificate-verified TLS using the configured DNS host as SNI
and verification identity before exchanging RFC 7858 length-prefixed messages.
The Core-wide managed-operation permit owns resolution, dial, handshake, and
exchange cancellation. The TUN raw-DNS proxy uses the same TLS identity and
pools only fully established protected streams. Apple and Android preflight
recognize the same authority grammar and port default so mobile bootstrap can
pin domain-valued DoT endpoints before tunnel establishment.

## Twelfth vertical slice: managed DNS over HTTPS

The parser accepts routed `https://host[:port][/path][?query]` and explicit
provider-local `https+local://...` name servers. Port 443 and path `/` are the
defaults; paths and queries are preserved, while userinfo, fragments,
non-ASCII/control data, malformed authorities, and tunnel-owned literal
addresses fail closed.

The managed query transport opens the selected routed or protected local TCP
carrier, performs certificate and configured-name verification with ALPN `h2`,
and sends one bounded RFC 8484 POST. The initial implementation opens one HTTP/2
connection per exchange; persistent pooling is a later hardening increment.
TUN UDP queries use the same core-owned query transport and operation cap. TUN
TCP queries are decoded from RFC 7766 frames and translated into independent
DoH requests, with response correlation checked before the frame is returned.
Apple and Android preflight recognize identical host, port, path, and bootstrap
semantics before their tunnel-owned DNS route is installed.
